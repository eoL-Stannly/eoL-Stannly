# Topic Clusters & Content Architecture

## Overview
Topic clusters are an SEO content strategy that organizes content around core themes. A pillar page covers a broad topic comprehensively, while cluster pages dive deep into subtopics, all interlinked.

## Why Topic Clusters Work
- Google evaluates topical authority — sites that cover a topic thoroughly rank better
- Internal linking between related pages passes relevance signals
- Users find comprehensive resources, improving engagement metrics
- Reduces keyword cannibalization by clearly defining page purposes

## Structure

### Pillar Page
- Broad, comprehensive overview of the core topic (2,000-5,000+ words)
- Targets high-volume, competitive head terms
- Links out to every cluster page
- Serves as the hub of the topic cluster
- Example: "The Complete Guide to Technical SEO"

### Cluster Pages
- Deep-dive into specific subtopics (1,000-2,500 words)
- Target long-tail, lower-competition keywords
- Link back to the pillar page and to related cluster pages
- Example subtopics: "Core Web Vitals Optimization", "XML Sitemap Best Practices"

### Linking Pattern
- Every cluster page links to the pillar (with keyword-rich anchor text)
- Pillar links to every cluster page
- Related cluster pages cross-link where contextually relevant
- This creates a tightly connected topical graph

## Building a Topic Cluster

### Step 1: Identify Core Topics
- What are your business's key service areas or expertise domains?
- What broad topics does your audience search for?
- What topics do competitors build authority around?

### Step 2: Map Subtopics
- Use keyword research to identify subtopic opportunities
- Check People Also Ask for question-based subtopics
- Analyze competitor content to find gaps
- Organize into a content map (spreadsheet or visual mind map)

### Step 3: Audit Existing Content
- Map existing pages to the cluster framework
- Identify content that can be updated vs. created from scratch
- Consolidate thin/duplicate pages covering the same subtopic
- Fix orphan pages by linking them into relevant clusters

### Step 4: Create & Optimize
- Write pillar page first (or update an existing broad guide)
- Create cluster pages in priority order (highest traffic potential first)
- Ensure consistent internal linking pattern
- Add schema markup (Article, BreadcrumbList, FAQ where relevant)

## Measurement
- Track cluster-level organic traffic (aggregate all pages in the cluster)
- Monitor pillar page rankings for head terms
- Track internal link equity flow with crawl tools (Screaming Frog, Sitebulb)
- Measure time-on-cluster (do users explore multiple pages?)
